# Design Spec: "Aurora Glass" habit tracker

Futuristic, calm, high-contrast. Bento-grid layout, glass cards, soft glow. Dark theme is the default. Light theme follows the pastel look: white cards, big radii, soft tinted tiles. Each habit's own color is the only strong color on screen; everything else is neutral.

## 2. Habit color rules (important)
- Habit color is used for: check ring/fill, progress bars, chart lines, heatmap cells, dots, tile tint, glow.
- Habit color is NEVER used for body text on a surface. Names stay text-primary.
- `readableColor(hex, theme)` in src/lib/color.ts: if contrast against the surface is below 3:1, raise lightness (dark theme) or lower it (light theme) until it passes. Use this for every foreground use of a habit color, so very dark or very light custom colors still show up.
- Tints: `color-mix(in srgb, <color> 22%, transparent)` for tile backgrounds, 35% for borders, 55% for glows.

## 3. Typography
- Headings and big numbers: "Space Grotesk" (Google Font). Body and UI: "DM Sans".
- Greeting/page title 32/40, weight 700. Hero numeral 56/56, weight 700, tabular-nums. Section title 18/24, 600. Habit name 17/24, 600. Body 15/22, 400. Caption 12/16, uppercase, tracking .08em, text-muted.

## 4. Shape, spacing, depth
- Radius: app shell 32px, cards 28px, tiles 24px, inputs 16px, buttons/chips/pills fully round.
- 4px spacing scale. Card padding 20px mobile, 24px desktop. Grid gap 16px mobile, 20px desktop. Page padding 16px mobile, 32px desktop. Max content width 1280px.
- Never use flat black cards with only a border. Every card has glass + soft shadow.

## 5. Layout shell
- Desktop (>=1024px): floating rounded shell inset 16px from the viewport edges over the aurora background. Slim 72px left rail with:
  - Top: logo mark (48px) in a glass tile; wordmark "Habit Tracker" present but visually hidden on the narrow rail.
  - Middle: Today, Overview, Settings as circular 48px icon buttons. Active: accent-gradient fill with glow. Inactive: surface-2 circle.
  - Bottom: Profile — the user's 48px avatar circle (icon fallback), active state with an accent-gradient ring when on /profile. No theme toggle in the rail; the theme toggle is a compact sun/moon icon button on the Today header.
- Mobile: no rail. Floating bottom dock, glass pill, 64px high, 16px from bottom and sides, 3 icon buttons (Today, Overview, Settings), respects safe-area inset. Content gets bottom padding so the dock never covers it. Profile is reached via the avatar in the Today header; Settings has a "View profile" link.
- Header on every page: greeting block (avatar, time-of-day greeting, "Hi, <name>", date) on the left, primary action pill on the right.

## 6. Components
- **Primary button:** 48px, accent-gradient, white text, glow shadow (0 10px 30px -8px accent at 60%). Hover: brightness 1.08 and translateY(-1px).
- **Secondary button:** glass pill, border, same height.
- **Habit tile (Today):** min-height 132px, background linear-gradient(145deg, habit 22%, habit 6%), border habit 35%. Top-left 44px circular check button: pending = 2px habit-color ring; done = filled habit color, white check, glow; **skipped day = dashed muted habit ring (45% color-mix), no pop/burst**. Habit name below (plain text, not a link), then a **"Skipped" caption chip when the day is skipped** (muted, before the streak chip), then the streak chip (flame icon + number) on the right. A skipped tile is muted overall (50% saturation, 80% opacity), its numeric bar is hidden and its value button shows "Skipped" instead of the number (never a 0%-miss), and it keeps its slot in the ring layout. Numeric habits show a 6px rounded progress bar in the habit color plus "12 / 30 min" (value / target unit, never repeat the number). Edit icon appears on hover and is always visible on mobile. **A "more" icon button (three dots) sits next to the pencil — same size (44px, hover-visible on desktop) — opening a small glass `popover-solid` menu with "Skip \<day\>" / "Undo skip" for the selected date, closing on outside click/Escape (CompletionCard popover pattern); the tile lifts to `z-10` while the menu is open, and the menu is disabled in reorder mode.** Below the ~232px container-query threshold only the more button shows, and the menu gains an "Edit habit" item (mirrored in JS with a ResizeObserver). Hover: lift 2px, border brighter. **The whole tile is a stretched link to the habit's detail/overview page** (absolute-inset overlay, sr-only label); exactly four controls paint above it and keep their own behavior: the check button (toggle), the pencil (edit page), the more menu (skip/undo) and the numeric value button/editor (log value). In reorder (jiggle) mode the overlay link is inert and the pencil/menu are disabled. **Dense columns (5-up ≥1280px):** the grid item is a CSS container; below a ~232px column the tile auto-compacts (min-height 104px, 14px padding, 36px check ring, smaller name/streak/value type) and invisible `::after` pads keep every control's effective tap target at ≥44px — full density applies on 1-up mobile columns.
- **Progress rings (hero):** concentric SVG rings driven by `src/lib/rings.ts` — ring order follows habit order from the outside in, exactly as `layoutRings` returns it: up to 7 habits each get a full ring of their own color (outermost = first); with more than 7, the first habits share the outer rings (equal arcs, up to 4 per ring: 50%/33%/25%…) and the remaining habits get full inner rings, capped at 28 shown habits. Each slice carries a 12%-opacity track arc and a progress arc (boolean = whole arc when done; numeric fills value/target clockwise from the slice start), 6px rule gaps with round caps. Geometry comes from `ringGeometry`, which packs the rings edge to edge between a ≥96px free center and the rim and centers them in the band: strokes are ~12px for 1–5 rings and thin to ~8.5px at 7, while the center hole shrinks as habits (rings) are added — from ~156px at one ring down to its 96px minimum — so there is never a large vacant middle. Center text counts ALL active habits ("3 / 12 done today") minus the habits skipped that day, and a skipped habit's tooltip says "skipped" (a neutral vacation day says "vacation", unless the entry is done — done wins); the numeral scales down for big counts and the caption is hidden when the center gets tight. **Vacation mode:** while the logical today is inside a break the hero passes `paused`, so the center shows "Paused" instead of the done/total pair. Hovering or tapping an arc shows a small glass tooltip (habit-color dot + name + "done"/"3 of 5 min"); targeting is a nearest-arc polar picker with a ≥24px tolerance — taps never toggle. Per-arc `aria-label`s plus a `role="img"` summary on the SVG.
- **Stat tile:** glass, caption label on top, big numeral, small delta chip with arrow (success or danger).
- **Chips (habit toggles):** 36px pill, small dot in habit color. Selected: habit 20% fill and habit 40% border. Unselected: 50% opacity.
- **Range switch:** segmented control with a sliding accent pill behind the active option, 40px high, equal-width segments, white-space nowrap. Under 400px uses short labels ("30d", "90d", "1y").
- **Color picker:** 10 preset round swatches (32px) with a ring on the selected one, plus a "custom" swatch that opens the native color input.
- **Inputs:** 52px, surface-2, 16px radius, 1px border, accent focus ring with glow.

## 7. Charts
- Line chart: monotone smooth curves, 2.5px stroke in the habit color, gradient area fill (habit 30% to 0%), soft glow via drop-shadow(0 0 8px habit 50%). Horizontal grid only, dashed, chart-grid color. No vertical grid, no axis lines. Axis labels 12px chart-axis.
- Active point: 8px dot with a 3px white ring, as in the reference. Tooltip: glass card, 16px radius, colored dot, habit name, value.
- Bars: 10px wide, fully rounded tops, 6px gap, habit color; today's bar glows.
- **Heatmap (HabitDetail):** 14px cells, 4px radius, 4px gap; levels at habit 12%, 35%, 65%, 100%; the top level has a small glow. Month labels above, weekday labels left; month labels are thinned (`sparseMonthLabels`) — a month that starts within ~3 columns of the previous label is dropped and the roomier month keeps its name (no DEC/JAN collisions). **Skipped days render as neutral outlined cells** (transparent fill, 1.5px `color-mix(in srgb, fg 40%, transparent)` border — never a 0%-miss fill), the tooltip/aria text says "Skipped", and a small legend sits under the grid (Done in full habit color; Partial at 35% for numeric habits; Skipped as the outlined sample; **Vacation as a second outlined sample** — a vacation day is neutral with the same look, and a done entry on a vacation day paints normally; Not completed in surface-2). **Tapping a day cycles empty → done → skipped → empty** via `nextDayAction`/`dayActionFor` in `src/lib/dayStatus.ts` (a done-but-below-target numeric row is "empty", so the first tap marks it done at target).
- Completion card (Today): **single-color intensity ramp** — the user picks ONE color for the whole card (palette popover with the standard color presets + native picker), and every day cell/bar is filled with that color via `color-mix(... N%, transparent)` where N follows the day's completion share (0 = neutral track, then 20…100%). It anchors to **logical today** (the day-start-adjusted real day, independent of the backfill date pill), is non-interactive, and the chosen view + color persist in localStorage (`completion-view` / `completion-color`, default `#6366F1`).
- Charts always have an empty state (soft illustration-free message plus "Check in a habit to see your score").

## 8. Page layouts
- **Today (bento):** desktop 12-column grid. Row 1: Hero card (rings + "3/4 done" + motivational line + overall streak, 5 cols), Completion card (7 cols; always the same height as the hero card — week bars flex into the leftover room, month/year views shrink to fit **inside that same height**, they never grow the card). Header row: "This week/This month/This year" title + "% done per day" caption, a **Week | Month | Year segmented pill** and a palette button opening the color picker popover. Views: week = 7 rounded bar pills (height = share, single-color intensity fill, today glows); month = calendar grid of the current month (7 columns Sun–Sat ≤420px; weekday letters on top; each row shares the leftover body height so cells stay short rectangles, day number per cell, cells filled by intensity, blanks for lead/future); year = GitHub-style heatmap over a **rolling 10-month window ending at the current month** (columns flex `1fr` to the card width — **no horizontal scrollbar**; 10px rows, month labels on top, Sun–Sat rows with Mon/Wed/Fri labels) + a "Less → More" intensity legend under the month/year views. Row 2: habit tiles in a responsive grid (1 mobile, 2 tablet, **user-picked ≥1024px**: a "Per row" glass stepper (− value +, 1–6, clamped buttons, `aria-live` value, persisted in `localStorage['tile-columns']`, default 5) writes `--tile-cols` on the grid and an unlayered media rule applies `repeat(var(--tile-cols), minmax(0,1fr))` — 1 = full-width tiles, more = narrower tiles that compact via the `.tile-cell` container query below ~232px). Header: compact circular theme icon button (52px round glass circle matching the date pill's height — sun in dark / moon in light, rotate + cross-fade swap, left of) the date pill with prev/next arrows and a calendar button. **Day-start caption:** when the logical date differs from the real calendar date (day-start setting after midnight), a small caption is shown **between the greeting block and the header controls, centered in the leftover space** (`lg:flex-1 text-center`): "Counting as <weekday, date> until <time>"; on mobile it sits between greeting and controls; hidden when the dates match.
- **Today vacation banner:** while the logical today falls inside a vacation period, a glass banner sits above the bento row: "Vacation mode · habits are paused" (caption "Nothing breaks a streak — check-ins still count.") with a right-aligned accent **Resume** pill (44px) that ends the ongoing break via `endVacation`. The hero center shows "Paused" (see §6) and the today-active tiles are muted like skipped ones but with a "Vacation" caption (a legend-style row-status note: the "more" menu still says "Skip \<today\>" because no skipped row exists; a check-in flips the tile back to normal immediately — done wins). Vacation-day neutrality flows into every stat through `vacationDatesInRange` (§10 rule in AGENTS.md).
- **Today reorder (jiggle) mode:** a 350ms long-press (8px tolerance, mouse + touch sensors; keyboard drags supported) on a tile lifts it into reorder mode and enters the mode via `onDragStart`. All tiles wiggle ±1.2° at 140ms ease-in-out infinite alternate, desynced by negative per-tile delays; inside the mode drags start after a 4px nudge instead of the long-press, the window auto-scrolls near the viewport edges (threshold y 0.2, acceleration 10), and touch scrolling is locked on the tiles while dragging. The dragged tile is a DragOverlay copy portalled to `document.body` (the shell carries `backdrop-filter`, which would otherwise trap the fixed overlay inside its containing block) at 1.04 scale with a stronger habit-colored glow while its source slot dims, sized to the source tile's measured rect, `pointer-events: none`, above the dock and toasts. The sortable attributes/listeners live on the tile's wrapper `<li>` at all times (`aria-roledescription="sortable"` is always in the DOM), so plain taps still reach the check-in/edit/link controls outside the mode and a swallow window (~150ms, set on drop) eats the trailing click after a drag. The header "Add habit" pill becomes "Done" (accent gradient) with a "Drag to reorder" caption; Escape or Done exits. Check-in circles, edit buttons and tile links are disabled and dimmed; native selection/long-press chrome is suppressed on tiles (`touch-action: manipulation` outside the mode, `none` inside). A drop saves the new order via `reorderHabits` with an "Order saved" toast (error toast if it rolls back).
- **Overview:** header with range switch. Row 1: three stat tiles (average score, best habit, needs attention) — Best habit and Needs attention are stretched links that drill into those habits' detail pages (habit name underlines on hover). Row 2: large chart card with the chip row inside it. No per-habit card list (removed — duplicated the Today-tile links; drill-in goes through the stat tiles).
- **Settings:** two-column on desktop. Left column: the **Day card** (title "Day", caption "A check-in after midnight counts for the previous day until this time", a glass **listbox popover** — trigger styled like `.input-field` with a rotating chevron, options 12 AM (midnight) … 6 AM in an **opaque** glass-card list (`popover-solid`, so the text beneath never bleeds through) with all seven options shown at once (no max-height, no scrollbar — the full 12 AM…6 AM list is always visible) with the selected row accented + check, outside-click/Escape close; instant save with a small "Saved" chip or error chip — NOT a native `<select>`, whose OS popup ignores the theme; **while the listbox is open the whole Day card lifts to `relative z-10`** so later-in-DOM sibling glass cards (Data card underneath, Habits card at right) can't paint over the popover — every `.glass-card` is its own stacking context via `backdrop-filter` and would otherwise cover it at `z-auto`; CompletionCard's color picker applies the same conditional lift) and a live line "Right now: counted as <weekday, date>" (plus an after-midnight note when the logical date differs from the real calendar date). Right column: Habits card (manage rows with color dot, plain-text name and Archive/Restore — no per-row links, no edit pencil (editing lives on the Today tile) and no "Archived" chip; the Restore button alone marks an archived row — **2-up at ≥640px**, 1-up mobile; each row is a CSS container and compacts below ~272px). The **Account card was removed** (user request; profile/email live behind the Today-header avatar and Profile page) and the Day card takes its spot; the header caption is "Habits and preferences". Under the Day card sits the **Vacation card** (owned by `VacationCard.tsx`, 40ms): title "Vacation", caption "Pause all habits for a while…", a full-width `role="switch"` row — checked = ongoing break from today, thumb accent — labeled "Pause all habits"/"Habits are paused" (the caption line names the covering period), then a **"Schedule a break"** form (From + To `<input type="date">` 44px fields, an empty To means ongoing, past dates allowed for backfill, inline `validatePeriod` errors in a red chip list, "Add break" accent pill disabled until a From date) and a **Breaks list** ("12 Oct – 18 Oct" / "Since 25 Oct · ongoing") with a 44px hover-danger trash icon per row whose delete runs behind the shared **ConfirmDialog** ("Delete break?"). Beneath it sits the **Data card** (owned by `BackupCard.tsx`): JSON backup export — caption "Export or import a JSON backup of your habits and check-ins. Profile photos aren't included.", a 44px label row with an accent-colored "Include profile details" checkbox (default off; the backup then carries the profile row minus `avatar_path`/email), and a 44px accent "Export backup" pill with a `progress-spin` ring + "Exporting…" while busy — and the **import**: a 44px **success-tinted** "Import backup" pill (`border-success/35 bg-success/15 text-success`, hover `bg-success/25`, same 44px + radius as its sibling so the pair reads as Export = accent / Import = green) driving a hidden `<input type="file" accept="application/json,.json">`. Choosing a file parses + plans it (`parseBackup`/`planImport`; files over 20 MB are rejected before reading) and opens the **ImportPreviewDialog** (§13, ConfirmDialog pattern): file name + export date, counts "N new · N existing" for habits and entries, the entry date range, parse warnings, and three option rows — "Overwrite with the backup" (default OFF: keep what's already in the app), "Restore settings" (day-start hour; default checked only when the user has no `user_settings` row yet) and "Restore profile details" (only when the file has a profile; default off, never the photo/email). Import is disabled with "Nothing to import: everything in this file is already in your app." when nothing is new and no option is selected; while running the Import button shows "Creating habits…" or "x / y entries" via `Intl.NumberFormat`. Success closes the dialog with an "Imported N habits · N entries" toast (or "Nothing needed importing"); a failure keeps the dialog open with an error chip reporting that what was imported has been kept and re-running is safe. Export/import toasts use the fixed glass-pill (Profile pattern). No Appearance card — the theme toggle is the icon button on the Today header.
- **Login:** centered glass card over the aurora background, logo mark above, gradient primary button.

## 9. Motion
- Easing cubic-bezier(.2,.8,.2,1). Durations: hover 160ms, page content 300ms.
- Page load: cards fade up 12px with 40ms stagger.
- Check-in: ring-pop (scale 1 to 1.15 to 1 in 280ms) plus a short burst of 6 small dots in the habit color; the hero ring arcs morph to their new fill (stroke-dasharray) in 400ms; big numbers count up.
- Rings and chart lines draw in on first render (900ms).
- Reorder: other tiles slide to make room at 200ms (dnd-kit default easing); the hero rings animate radius, slice position (rotation) and fill in 400ms.
- Respect prefers-reduced-motion: disable bursts and draw-ins; in reorder mode the wiggle becomes a static dashed outline and drags still work.

## 10. Do and don't
- Do keep neutral surfaces and let the habit colors carry the color.
- Do keep tap targets at least 44px.
- Don't use habit colors for text, uppercase habit names, or flat black card backgrounds.
- Don't add new dependencies except an icon set already in use. Animations are CSS and SVG only.
- Don't leave a page as one narrow centered column on desktop; use the grid.

## 13. Dialogs
All confirmation dialogs use the shared `ConfirmDialog` component (`src/components/ConfirmDialog.tsx`), rendered via `createPortal` into `document.body` so no parent with `backdrop-filter`, `transform`, `filter`, or `overflow` can break the blur.

- **Scrim:** full-screen layer behind the dialog. `rgba(4,6,14,0.55)` in dark, `rgba(15,23,42,0.28)` in light, plus `backdrop-filter: blur(10px) saturate(120%)`. Fades in over 160ms. Clicking the scrim cancels.
- **Dialog panel:** glass, not solid. Width `min(420px, calc(100vw - 32px))`, radius 28px, padding 24px.
  - Dark: background `linear-gradient(145deg, rgba(34,38,64,0.78), rgba(14,18,36,0.72))`; border `1px solid rgba(255,255,255,0.14)`; `backdrop-filter: blur(28px) saturate(150%)`; shadow `inset 0 1px 0 rgba(255,255,255,0.10), 0 30px 80px -20px rgba(0,0,0,0.7), 0 0 60px -20px color-mix(in srgb, var(--accent) 35%, transparent)`.
